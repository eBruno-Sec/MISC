# Engineering Principles

- Preserve public contracts.
- Prefer explicit types and schemas.
- Keep business logic independent of UI.
- Use pure calculator functions.
- Keep state transitions deterministic.
- Validate at boundaries.
- Fail safely.
- Make retries idempotent.
- Log decisions, not sensitive payloads.
- Prefer composition over inheritance.
- Avoid unnecessary global state.
- Keep components small and testable.
- Document architectural decisions.
- Require code review for financial formulas, migrations, and security-sensitive changes.
